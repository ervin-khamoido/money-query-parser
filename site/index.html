GETTING STARTED

A small API you can read in a minute.

Create a parser once with the currencies and number format your application supports. Parse strings into a discriminated result. This is an ESM package with TypeScript declarations included.

import { createMoneyQueryParser } from 'money-query-parser';

const parse = createMoneyQueryParser({
  currencies: { EUR: 2, USD: 2, JPY: 0, BTC: 8 },
  defaultCurrency: 'EUR',
});

const result = parse('-12.50 EUR');

if (result.ok) {
  console.log(result.query);
  // { kind: 'exact', currency: 'EUR', scale: 2, amount: '-1250' }
} else {
  console.log(result.error.code, result.error.message);
}

Node.js 22+ for Node consumers. Standard ECMAScript APIs in the browser. No framework, account or backend service required.

Format a query

formatMoneyQuery(query, options?) produces a deterministic, parseable major-unit expression. It writes all fractional digits, an explicit currency suffix and consistent operator spacing without floating-point money arithmetic.

import { formatMoneyQuery } from 'money-query-parser';

formatMoneyQuery({
  kind: 'range', currency: 'EUR', scale: 2,
  min: '-1000', max: '2000',
});
// '-10.00..20.00 EUR'

Options include the decimal and grouping separators plus the validator's optional currency allowlist and digit limit. Space variants are preserved when formatting. Parsing the result preserves a clean AST when currencies, separators and resource limits match.

Invalid ASTs throw TypeError with a structured validation error in cause. Invalid options throw configuration errors. For untrusted input, validate first.

Validate an unknown AST

validateMoneyQuery(value, options?) returns a typed success or first error. It checks kind, canonical uppercase currency, scale 0–18, integer strings, operator and range order. Successful output is a fresh object containing only the fields for its kind.

import { validateMoneyQuery, formatMoneyQuery } from 'money-query-parser';

const checked = validateMoneyQuery(payload, {
  currencies: { EUR: 2, JPY: 0 },
});
if (checked.ok) {
  console.log(formatMoneyQuery(checked.query));
} else {
  console.log(checked.error.code, checked.error.path);
}

Without a currency map, validation is structural. Supply your backend's currency allowlist to enforce its authoritative scales. Amounts must be canonical minor-unit strings: no plus sign, leading zeros, negative zero or decimal part. The default magnitude limit is 38 digits; the configurable maximum is 1000.

Required fields must be own data properties; inherited values and accessor fields cannot supply them. Unknown fields are removed. Validation errors contain code, path, message and details. The path is a field name or $ for the whole value. Invalid configuration throws; malformed values return failures. JSON decoding and authorization belong to the host.

Codes: INVALID_QUERY, INVALID_KIND, INVALID_CURRENCY, UNKNOWN_CURRENCY, INVALID_SCALE, SCALE_MISMATCH, INVALID_AMOUNT, AMOUNT_TOO_LARGE, INVALID_OPERATOR, REVERSED_RANGE.

Expression syntax

Amounts are entered in major units. The result uses integer strings in minor units: 12.50 EUR → "1250". The examples below use EUR with scale 2 as the default.

ExpressionMeaningMinor units
12.50 EURExact amount1250
EUR -12.50Currency prefix, negative value-1250
10..20Inclusive range[1000, 2000]
> 10 / >= 10Strict / inclusive minimum1000
< 10 / <= 10Strict / inclusive maximum1000
USDCurrency-only filter—

Specify a currency once, before or after the entire expression, separated by whitespace. Codes are case-insensitive, use 3–8 ASCII letters and must be configured. Without a currency token, the default is required. Equal range bounds are valid; reversed bounds are rejected.

Format is a setting, not a guess.

Grouping is disabled by default. 1,234 is rejected unless you explicitly enable comma grouping or choose a decimal-comma format. The same string can mean different things under different configurations.

Configuration

The application owns currency metadata. Each currency maps to its number of fractional digits; there is no implicit two-decimal fallback. Options are validated and copied when the parser is created.

OptionDefaultContract
currenciesRequiredNon-empty code-to-scale map. Integer scales 0–18.
defaultCurrencyNoneA configured currency code.
decimalSeparator.Dot or comma.
groupSeparatornullDot, comma, space, NBSP or narrow NBSP; different from the decimal separator.
maxInputLength2561–4096 UTF-16 code units, before trimming.
maxAmountDigits381–1000 canonical minor-unit magnitude digits per operand, excluding sign and leading zeros.

Enabled grouping requires groups of three digits after the first group. Space grouping also accepts both NBSP variants. Excess fractional digits are rejected, including trailing zeros. -0.00 normalizes to "0".

Result types

Narrow by ok, then by query.kind. Amounts remain exact in JSON without a custom serializer. These fields are readonly in the exported TypeScript types.

type MoneyQuery =
  | { kind: 'exact'; currency: string; scale: number; amount: string }
  | { kind: 'comparison'; currency: string; scale: number;
      operator: 'gt' | 'gte' | 'lt' | 'lte'; amount: string }
  | { kind: 'range'; currency: string; scale: number;
      min: string; max: string }
  | { kind: 'currency'; currency: string; scale: number };

type ParseResult =
  | { ok: true; query: MoneyQuery }
  | { ok: false; error: { code: ParseErrorCode; message: string;
      span?: { start: number; end: number }; details?: ParseErrorDetails } };

Errors are part of the API.

Malformed search strings return ok: false. Localize the UI using stable error codes. Invalid construction settings throw TypeError or RangeError. Non-string input is outside the API contract.

CodeMeaning
EMPTY_INPUTNothing remains after trimming.
INPUT_TOO_LONGRaw input exceeds the length limit.
UNKNOWN_CURRENCYThe currency token is not configured.
MISSING_CURRENCYNeither explicit nor default currency is available.
INVALID_SYNTAXThe expression does not match the grammar.
INVALID_GROUPINGConfigured grouping is malformed.
PRECISION_EXCEEDEDToo many fractional digits. No rounding is applied.
AMOUNT_TOO_LARGEThe minor-unit magnitude exceeds the digit limit.
REVERSED_RANGEThe minimum exceeds the maximum.

The first detected error is returned. Free text such as refund may be treated as an unknown currency token. The host UI decides when monetary parsing applies; avoid silently turning a mistyped amount into a free-text search.

Point to the exact problem.

Every parser-created failure includes span and structured details. Source spans are half-open UTF-16 offsets into the original, untrimmed string, compatible with browser input selection. Empty spans mark insertion points.

// parse('12.345 EUR').error
{
  code: 'PRECISION_EXCEEDED',
  message: 'This currency supports at most 2 fractional digits; rounding is disabled.',
  span: { start: 5, end: 6 },
  details: { currency: 'EUR', allowedScale: 2, actualScale: 3 }
}

Limits expose limit/actual; unknown currencies expose currency; grouping exposes groupSize and expected. Other syntax and range failures describe the expectation. Diagnostic fields are optional in the exported interface for compatibility with caller-created 0.1 errors. Codes, messages and the parsing grammar remain unchanged.

Parse here. Execute in your application.

The AST is independent of a database. Compile it into your backend's filters and bind all values. The playground's SQL tab uses the repository's fixed-schema PostgreSQL example.

// parse('10..20 EUR') → PostgreSQL example
{
  text: 'currency = $1 AND amount_minor BETWEEN $2::numeric AND $3::numeric',
  values: ['EUR', '1000', '2000']
}

The example assumes amount_minor NUMERIC(38, 0). Its output is tested; no SQL is executed by the library. Keep scales aligned with storage, check backend numeric limits and apply account/tenant authorization on the server. Validate client-supplied ASTs or reparse the string.

Precision by construction.

01

Decimal strings in, integer strings out.

Conversion uses string operations instead of parseFloat × 100. Large amounts retain their digits; internal BigInt comparisons order range bounds numerically.

02

Explicit configuration over guessing.

Separators and currency scales come from your product settings. A private configuration snapshot keeps an existing parser stable when the caller changes its options object.

03

A bounded, inspectable contract.

One factory, four filter types and typed failures. Length and digit limits bound inputs before range comparison. Parsing and data access remain separate.

Know the boundaries.

This package parses monetary filters. It does not provide ledger arithmetic, currency conversion, an ISO currency database, text classification or search execution. Currency symbols, exponent notation, accounting parentheses, automatic locale detection, mixed-currency ranges and Indian digit grouping are outside the grammar.

The distribution is ESM. No separate CommonJS build is provided. Tests cover exact conversion, malformed inputs, generated examples, type narrowing and an isolated tarball consumer. They are not a proof of every possible integration.

Found a case the grammar should support? Include the exact input, configuration and expected interpretation in an issue.
